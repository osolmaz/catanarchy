# AGENTS.md

- Use Node.js 22.19 or later.
- Use TypeScript with strict compiler settings. Do not weaken a compiler option to make code pass.
- Keep `packages/engine` deterministic, headless, and independent from Pi, network clients, databases, and user interfaces.
- Keep player-visible observations separate from the authoritative state. Tests must prove that private cards and hidden development cards do not leak.
- Use Effect for typed failures, dynamic-boundary decoding, resource management, concurrency, and service composition. Keep simple game calculations as plain pure functions.
- Use an explicit seeded random source. Do not call `Math.random()` in production code.
- Represent changes as commands and ordered events. A replay from the same configuration and commands must produce the same events and state.
- Follow `docs/ENGINE.md` as the Milestone 1 implementation contract. Update it before changing a locked decision.
- Keep remote and replay viewers read-only. The trusted local hot-seat client can send setup commands to the native engine. Follow `docs/VIEWER.md` for viewer data, privacy, rendering, and tests.
- Keep free-form messages separate from binding game operations. The engine validates and commits structured trades. The harness records arguments, promises, and other speech.
- Keep Pi integration under its own boundary. Use documented Pi SDK APIs unless a separately approved plan requires a core change.
- Follow the dependency boundaries in `slophammer.yml`.
- Do not add game artwork, copied rulebook text, or other game assets.
- Do not add mutation testing. Use unit, property, replay, information-boundary, and conformance tests.
- Start every model run at the deepest thinking level the harness accepts, which is `--thinking=max`. Use a lower level only when the user names another level, when the model does not accept the deepest level, or when its reasoning at that level makes the game unplayable. A run that used a lower level must say so, and give the reason, in its launch record.
- Keep the level that each provider receives in `config/thinking-levels.json`. A live run passes `--thinking-levels=config/thinking-levels.json`, so the map is version controlled and the launch record states it. A run pin in that file is a design choice and must carry its reason. Do not edit a level map in Pi's cache store.
- The finalization grace defaults to 300 seconds, which is the grace of one decision, so a live model run needs no flag for it. The grace exists for a model that spends its answer in prose. When the grace is empty the harness replaces that decision, and the loss is invisible in the result: a 60-second grace removed 41 terra decisions in the seed 47 games, and a 300-second grace removed none of the same kind. A run that used a smaller grace must say so, and give the reason, in its launch record.
- A replaced decision must not change the position when the rules allow a neutral action. The harness ends the turn, rolls, or moves the robber in that case. Record the replaced decisions and the exhausted pools from `run.completed.decisionSummary`.
- Start a live game in the background, detached from the agent session: `setsid nohup <command> > <log> 2>&1 < /dev/null &`. A session reap, a closed terminal, or a restarted harness must not kill a running game. On 2026-09-14 a session reap killed four running games two hours in. Watch a detached run through its timeline and its package, not through the session that launched it. A killed run leaves a stale `run.lock`; remove it before a resume.
- Ignore any run that is not marked valid. A run counts as evidence only when its package holds a `VALIDITY.json` that says `valid: true`. The mark states its evidence, and `docs/RUN_VALIDITY.md` states the criteria, the published table, and how to mark a package again.
- Use Conventional Commits for commit messages and pull request titles.
- Run `npm run check` before finishing a change.
